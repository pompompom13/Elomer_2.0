# Архитектура ЭЛОМЕРА

React отображает формы, карты и результаты. Через `frontend/src/api.ts` он обращается к FastAPI. FastAPI проверяет запрос, вызывает нужный модуль расчёта или анализа и возвращает JSON, Excel или PDF. При обычном запуске FastAPI также раздаёт собранный интерфейс из `frontend/dist/`. В режиме разработки интерфейс обслуживает Vite.

## Сервер

| Модули в `backend/app/` | Что в них искать |
| --- | --- |
| `main.py` | Точка входа FastAPI, маршруты HTTP, модели входных параметров и подключение фронтенда |
| `planner.py`, `calendar_ru.py` | Рабочие дни и периоды, постановка визитов, порядок остановок, расчёт длительности и перебор вариантов расписания |
| `coverage.py`, `goal.py`, `advisor.py` | Квоты охвата по специальностям, оценка команды под цель, рекомендации и сравнительные сценарии |
| `projects.py`, `plan_results.py` | Сохранение проектов и версий расчёта, запуск многогородских расчётов и временное хранение отдельных городских планов в процессе API |
| `territories.py`, `territory.py` | Распределение объектов между медпредставителями и обработка зон. Состав пригородов и региональной базы учитывается в `territory.py` |
| `facilities.py`, `cities.py`, `city_stats.py` | Карточки учреждений, индекс городов, загрузка городских данных и городская статистика |
| `pharmacy_registry.py`, `lpu_registry.py`, `networks.py`, `care.py`, `dental.py` | Реестры аптек и ЛПУ, сети, амбулаторное и госпитальное звено, данные стоматологий |
| `doctor_sources.py`, `doctor_stats.py`, `norms.py` | Источники численности врачей, оценка по городу и учреждениям, нормативы времени |
| `market_analysis.py` | Сопоставление адресов заказчика по коду ДСМ, координатам или адресу. Расчёт ND по позиции, территории и дате и формирование Excel для обоих отчётов |
| `base_export.py`, `export_xlsx.py`, `project_xlsx.py`, `report_pdf.py` | Статистика и выгрузки базы, выгрузка города, выгрузка проекта и отчёты PDF |
| `client_bases.py`, `field_data.py`, `visit_reports.py`, `resume.py` | Обработка сохранённых источников заказчиков и полевых данных, разбор отчётов и возобновление фоновых загрузок |

Служебные команды находятся в `backend/tools/audit_base.py`, `backend/preload_all.py` и `backend/fix_overlaps.py`. Часть этих команд меняет городские данные. Для обычной сборки их запускать не требуется.

## Интерфейс

| Файл или группа в `frontend/src/` | Назначение |
| --- | --- |
| `main.tsx`, `App.tsx` | Запуск React, переключение разделов, состояние приложения и переходы между городом и проектом |
| `api.ts`, `types.ts`, `store.ts`, `format.ts` | Запросы к API, типы данных, состояние и параметры клиента, форматирование значений |
| `components/AllCities.tsx`, `BaseView.tsx`, `CityStatsView.tsx` | Общая база и карточка города |
| `components/ProjectsView.tsx`, `ProjectSpecialties.tsx` | Условия, специальности и результаты многогородского проекта |
| `components/ParamsForm.tsx`, `CitySettings.tsx`, `Territories.tsx`, `Calendar.tsx`, `DayDetail.tsx` | Условия городского плана, настройки времени, редактирование зон и расписание дня |
| `components/DataView.tsx`, `MarketAnalysis.tsx`, `NDMap.tsx` | Раздел «Данные», управление отчётами и рейтингом, городские маркеры и подписи ND |
| `components/PlanMap.tsx`, `DotsMap.tsx` | Карты маршрутов, учреждений и точек сверки |
| `styles.css`, `screens.css`, `theme.css` | Общие стили, стили экранов, тема и адаптация |

Для изменения расчёта начните с соответствующего модуля Python. Для изменения текста, состояния экрана или цвета проверьте компонент и его стили. Если меняется структура JSON, сверяйте модели в `main.py`, серверный ответ, `api.ts` и типы на стороне React.

## Рабочие данные

`backend/data/` содержит данные конкретной установки и исключена из Git. При переносе с рабочей установки сделайте согласованную копию папки, когда расчёты и фоновые загрузки завершены. Положите копию в `backend/data/` в новом клоне. Для новой установки с теми же справочниками и без истории переносите только нужные справочники и базы городов из согласованного снимка.

| Путь внутри `backend/data/` | Содержимое |
| --- | --- |
| `city_index.json`, `cities/`, `regions/` | Индекс и рабочая география для базы, сверки и маршрутов |
| `source/`, `doctor_stats.json`, `benchmarks.json` | Реестры, источники оценок и ориентиры для расчёта |
| `projects/` | Сохранённые проекты и результаты расчётов |
| `client_bases/`, `field_data/` | Сохранённые источники заказчиков и агрегаты полевых данных |
| `cache/` | Кэш и служебные отметки фоновых задач |

Конфигурация Caddy и файлы с хэшами паролей создаются на сервере. Docker подключает `backend/data/` как том. `deploy/pack.bat` создаёт архив для установки и включает в него рабочие данные. Передавайте такой архив отдельно от репозитория.

## Что проверяет GitHub Actions

Сборка фронтенда включает проверку TypeScript. Для бэкенда выполняются компиляция Python и импорт FastAPI с построением схемы OpenAPI. Эти проверки проходят без реестров и клиентских данных. Маршруты, географию и отчёты проверяют локально на рабочем снимке данных.
